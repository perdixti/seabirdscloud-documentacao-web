Imagens

          

            Ctrl+V com uma imagem no editor grava um PNG na pasta escolhida,
            insere o Markdown e incrementa o índice. O mesmo fluxo funciona pelo
            botão Imagem. O caminho no HTML pode ser diferente do caminho
            físico. Ao rodar no LXC, a pasta é do LXC; um caminho do Windows não
            aponta para seu computador remoto.
          

          

            O × da miniatura remove a imagem do Markdown; Ctrl+Z desfaz. Em
            Gerenciar imagens, selecione uma ou várias imagens para mover
            à pasta correta ou enviar à lixeira. A lixeira permite restaurar os
            arquivos e inseri-los novamente. Ler imagens de uma pasta
            encontra arquivos salvos antes desta atualização. Apagar a
            referência no texto também retira a miniatura, sem apagar o arquivo.
          

          

            No filtro Na lixeira, use Excluir definitivamente em
            uma imagem ou selecione várias para excluir em lote. A confirmação
            mostra os arquivos que serão apagados. Essa ação não pode ser
            desfeita.
          

          

            Os caminhos e as opções ficam em Configurar arquivos e nos
            três resumos acima do editor. Alterne entre Dividido,
            Editor e Prévia ou expanda a área de trabalho para
            escrever com mais espaço.
          

          
Templates e opções

          

            O template padrão é o template original do projeto. HTML escrito no
            Markdown é aceito por padrão, como na aplicação antiga. Você pode
            desativá-lo nas opções. Os blocos table,
            tablecard, os cards de código, os botões de copiar,
            | destaque e
            {{link: URL | Texto}} continuam disponíveis.
          

          
Site e repositórios

          

            Selecione a pasta do index.html para listar e editar seus HTML
            locais. A exclusão pede confirmação e envia a página para uma
            lixeira recuperável. Para enviar as mudanças e remoções ao GitHub,
            use
            Publicar alterações do site; essa revisão não regenera
            páginas.
          

          

            Você também pode clonar um repositório para uma pasta nova ou abrir
            o VS Code Web na mesma cópia local. No Windows, a inicialização pede
            sua aceitação dos termos do servidor. No LXC, configure um
            code-server com acesso à mesma pasta. Salve, atualize a listagem e
            revise o commit.
          

          
Publicar no GitHub

          

            O botão Publicar gera o HTML e abre uma revisão dos arquivos
            do repositório. Confira o destino, selecione os HTML e imagens, veja
            as diferenças e informe a mensagem de commit. O envio à main
            dispara a pipeline existente do GitHub Actions para o S3. A geração
            comum de HTML continua disponível pelo botão Gerar HTML.
          

          

            A pasta do clone pode ser informada em Configurar arquivos. O Git
            precisa estar instalado e autenticado no computador ou servidor que
            executa o aplicativo. Atualize a main local quando solicitado. Se o
            push falhar depois do commit, use Reenviar este commit. Os links e o
            botão Atualizar pipeline permitem acompanhar o deploy.
          

          
Histórico

          

            Configure a frequência em segundos e o máximo de versões. O
            histórico salva rascunhos Markdown; ele não gera nem publica HTML
            automaticamente. Históricos de projetos permite abrir projetos
            anteriores e os autosaves da pasta antiga. Antes de restaurar, a
            versão atual é salva.

Substituição e formatação

          

            As ferramentas trabalham nos arquivos da pasta escolhida, inclusive
            subpastas. Faça a busca, filtre, marque os arquivos e confirme a
            aplicação. Uma cópia anterior de cada arquivo alterado é guardada no
            diretório de dados do aplicativo em file-backups. Também são aceitos
            TXT, HTML, HTM, MD, CSV, JSON e XML em UTF-8.
